Hostel Operations · Infrastructure

VPS Migration Proposal

Assessing a move from shared cPanel hosting to a self-managed VPS, and comparing self-managed versus fully-managed operation.

Subject system: Hostel Operations (student/tenancy management) Candidate plan: Linux KVM VPS – Basic, RM28.90/mo Date: September 2026

Executive Summary

Recommendation

Migrate the Hostel Operations application to a self-managed Linux KVM VPS (Basic tier). The current shared cPanel host has two infrastructure-level faults that only the hosting provider can fix — a reverse-proxy misconfiguration and an outbound firewall blocking database connectivity — and both have required open-ended waits on provider support. A VPS removes that dependency entirely, at a lower ongoing cost than a managed alternative.

Background

Two faults were identified on the current shared hosting account while deploying this system, both outside of what the cPanel control panel can configure:

  • The Node.js reverse proxy only forwards requests for the exact root path (/); every other route — API endpoints, static assets, all application pages — returns a generic server error.
  • After that was partially addressed, outbound connections from the server to the application's external PostgreSQL database (hosted on Supabase) were found to be silently blocked at the network level (ETIMEDOUT), rather than reaching the database at all.

Both faults required escalation to the hosting provider's support team, with no fix guaranteed and no fixed timeline.

Recommendation

Assessment

Proceed with the self-managed Linux KVM VPS – Basic plan.

The Basic tier's specifications comfortably cover this application's needs, with RAM as the only figure worth monitoring as usage grows. Self-management directly eliminates the root cause of the current outage — dependency on a third party's support queue to fix infrastructure faults — while costing less than a managed alternative.

A managed service remains a reasonable option if the system's scale or data-security requirements grow to the point where dedicated, contracted security ownership becomes necessary. That is not the case at the system's current scale.
